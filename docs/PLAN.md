# Open Referee — v1 Implementation Plan

Open-source harness that reviews academic papers the way a referee for a top
journal would: deep single-paper analysis, literature grounding, adversarial
challenges, and a validated structured review report.

Design reference: the feedback schema of refine.ink — overall markdown report +
inline comments, each anchored to exact document text with a severity score
0–1. The schema is replicated; all content is generated by the user's own LLM
configuration.

## Decisions (agreed with the project owner)

- **Language:** Python everywhere (3.11+), async (FastAPI + httpx).
- **Packaging:** one artifact, two channels — PyPI package (installable with
  `pip` / `uv`, PWA static assets bundled inside the package) + Docker image
  wrapping the same package. No CLI in v1; the PWA is the only interface.
- **Frontend:** htmx + Alpine.js server-rendered PWA (vendored assets, no CDN),
  manifest + service worker for installability and offline report reading.
- **LLM roles:** strong / small / vision — each role independently bound to any
  configured provider, so roles can mix providers freely.
- **Provider types:** openai-compatible, anthropic, gemini, ollama, vllm —
  all first-class, cloud and local tested per release.
- **OpenAlex interface:** [`openalex-py`](https://pypi.org/project/openalex-py)
  (import `openalexpy`), async-native.
- **Web search:** user-configured engines in user-set priority order (Tavily,
  TinyFish, Brave), with failover down the list.
- **Review signals from review communities:** specialized web searches on
  PubPeer, OpenReview, PREreview (and similar) surface prior discussion of the
  paper and of its key citations; findings inform the verifier and challenger
  prompts.
- **Inputs:** PDF, LaTeX, Markdown, **DOCX**.
- **User-supplied literature:** reviewer can upload related-work PDFs alongside
  the manuscript; they are ingested the same way and injected into the
  literature context as prioritized reading.
- **Cost controls:** usage ledger per call, cost estimate from a per-model
  pricing table, configurable spend cap enforced before every LLM call
  (`BudgetExceeded` drains gracefully into a partial report).
- **Config:** single YAML file (`~/.open-referee/config.yaml`) + env-var
  secrets (YAML stores env-var *names*, never key values). The PWA settings UI
  edits the same file — one source of truth.
- **License:** MIT.
- **Exports:** JSON (canonical), markdown, PDF export of the review report.

## Review pipeline (staged, parallel, resumable)

| # | Stage | Role | Output |
|---|-------|------|--------|
| 1 | Triage | strong | domain, claims inventory, contribution statement |
| 2 | Literature survey | small | queries → context pack (OpenAlex + Crossref + web) |
| 3 | Review-community scout | small | PubPeer/OpenReview/PREreview signals for paper + key citations |
| 4 | Section verifiers | small/strong + vision for figures | candidate comments (math, consistency, claims-vs-evidence, notation) |
| 5 | Challenger | strong | adversarial re-read; missed weak points; candidate validation |
| 6 | Bibliography & novelty audit | small + search | phantom/miscited refs, missing key references |
| 7 | Meta-reviewer | strong | dedupe, severity 0–1, overall report draft |
| 8 | **Review validator** | strong | post-meta validation pass: every comment checked against the manuscript (quote exists, criticism substantiated), severity recalibrated, tone checked, fabrications dropped; overall report consistency-checked |
| 9 | Assembler | — | anchors resolved (fuzzy match w/ confidence; degrade to section-level), exports |

Events stream to the PWA via SSE; per-stage artifacts persist under
`~/.open-referee/runs/<id>/` so interrupted runs resume (incl. server restart).

## Report model

```jsonc
{
  "metadata": {"paper_title", "run_id", "generated_at", "model_roles", "usage"},
  "paper_summary": "str",
  "overall_feedback": "markdown",
  "comments": [{
    "id", "title", "section", "paragraph_anchor", "quote",
    "message", "score", "category", "anchor_confidence"
  }],
  "usage_summary": {"tokens_by_role", "estimated_cost_usd"}
}
```

## Test plan

- Unit: config precedence, anchor fuzzy matching, usage ledger/cap, provider
  adapters (respx-mocked HTTP), search router failover, ingestion per format.
- Integration: full pipeline on a short public-domain paper with FakeProvider
  (scripted comment + overall) → assert report JSON, anchors, exports.
- Server: TestClient page hits, settings save round-trip, SSE emission.

## Known risks & mitigations

- PDF/DOCX anchor fidelity → fuzzy matcher + confidence; unmatched comments
  degrade to section level, never dropped.
- Structured output on small/local models → schema-hinted JSON + parse-repair
  retry loop; per-provider caveats documented.
- Cost blow-ups → stage-level cap shares; ledger checked pre-call.
- openalex-py is young (0.1.x) → isolate behind a thin `OpenAlexClient`
  wrapper so it can be swapped without touching the pipeline.
